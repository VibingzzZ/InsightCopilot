## 降本：合并意图/情绪/风险三节点 + summary 按需跳过

用户目标（题干要求）：**降低 AI 分析成本**。原链路每次分析固定 5 次模型调用
（intent + emotion + risk_extraction + summary + reply，全走 deepseek-flash），
其中 intent/emotion/risk_extraction 三者**输入都只有同一条当前消息**，是最大可合并点。

改动（全部向后兼容，state 字段不变）：
1. **新增合并 schema** `app/agent/schemas/analysis.py::TriageAnalysis`：一次产出 intent+emotion+risk 三组字段。
2. **新增合并 Prompt** `app/prompt/triage.py::TRIAGE_PROMPT`（含 intents/emotion/risk 三段；结尾保留 "json" 字样，满足 deepseek-flash 的 json_object 约束）。
3. **新增合并节点** `app/agent/nodes/triage.py::triage_node`：单次 `run_structured`（route="fast"），fallback 复用 mock_intent/mock_emotion/mock_risk 组合。输出 `intent`/`emotion`/`emotion_trend`/`risk` 与原三节点一致。
4. **改图** `app/agent/graph.py`：`context → triage → risk_engine`（原 `context→intent→emotion→risk_extraction→risk_engine`）。节点数 10 → 8。
5. **summary 按需跳过** `app/agent/nodes/summary.py`：无历史（events/tickets/promises 均为空）时直接走 `mock_summary`，省一次模型调用，且**不置 degraded**（是优化非失败）。
6. **测试修复** `tests/test_realtime.py`：两个改写用例（adjust_tone / optimize_expression）改为 `monkeypatch` 强制 `gateway.is_available=False` 走 mock——因 fast 路由已指向真实 DeepSeek，真模型输出文案不固定，原断言依赖 mock 标记。

实测降本（真实 DeepSeek 调用，`cost.get_call_logs`）：
- 合并 triage：**3 次调用 → 1 次**，token **1888 → 1374（省 27%）**。
- 整条分析调用次数：
  - 无历史简单会话（物流）：5 → **2**（省 60%）
  - 有历史会话（退款）：5 → **3**（省 40%）
  - 高风险+图片（不良反应）：6 → 3 真实调用 + 1 Mock vision
- WS 流式节点序列验证：`context, triage, risk_engine, tool_query, evidence, summary, reply, fact_check`，reply 草稿非空。
- 全量测试：**77 passed**。

## 成本可观测接口 + WS 会话归集（对齐赛题"成本优化"加分项）

赛题明确「模型性能与成本优化能力」为加分项，要求"设计成本节约机制 + 可量化评估"。除合并降本外，补上可观测/可量化能力：
- 新增路由 `app/api/routes/cost.py`（已注册到 `routes/__init__.py`）：
  - `GET /api/cost/summary` —— 全局：总调用数、真实/Mock 调用数、总 token、按路由聚合。
  - `GET /api/cost/{session_id}` —— 单会话聚合 + 每次调用明细（route/model/tokens/degraded/latency）。
- `app/main.py` WS 端点：分析前后 `cost.set_session(session_id)` / 复位，使 WS 流也归集到会话（此前 WS 直连 `g.astream`、不经 run_copilot，token 记不到会话）。
- 验证：WS 发一条 → `GET /api/cost/{id}` 返回 `{calls:2, total_tokens:1824}`；`/api/cost/summary` 按路由拆分正常。全量测试 77 passed。

成本节约机制总览（可写进 PPT）：
1. 调用合并：intent+emotion+risk_extraction → triage（-2 次调用，token -27%）。
2. 条件跳过：summary 无历史不调；vision 无图不调。
3. 规则兜底：mock/规则命中即不调模型；模型失败自动降级，不重试轰炸。
4. 分层路由：fast/reasoning 可分别配置不同模型（当前同模型，配置化可换更便宜模型）。
5. 可观测与量化：`/api/cost` 接口 + `cost.py` 日志，可输出改前/改后 token 对比。
6. 稳定性：显式超时(20s)+max_retries(1)，避免卡死与无限重试。
