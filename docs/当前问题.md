     
  一、当前 V1 怎么实现（已完成的现状）
     
  1. 入口
     
  python -m app.agent.run 会依次跑三个 Case（退款 / 不良反应 / 物流），打印每个阶段的 state。真正的入口文件是 app/agent/run.py，核心是 graph.invoke(make_state(message))。

  2. 状态图（app/agent/graph.py）

  START → Context → Intent → Emotion → Risk Extraction → Risk Engine
                                                          │
                                            Conditional Edge (route_by_risk)
                                              ├─ normal → Tool Query → Evidence ─┐
                                              └─ high   → Adverse ───────────────┴→ Reply → END                                                                                                           

  9 个节点，risk_engine 后面按 risk_level 走条件边。这条链路已经完全成型。

  3. State（app/agent/state.py）

  CustomerState 分五层：输入层 → 理解层(intent/emotion) → 风险层(risk/risk_level) → 数据层(order) → 证据层(evidence，用 add reducer 累加) → 表达层(reply_draft)。

  4. 各节点职责

  ┌─────────────────┬──────────────────────────┬────────┬───────────────────────────────────────┐
  │      节点       │           文件           │  类型  │                做什么                 │
  ├─────────────────┼──────────────────────────┼────────┼───────────────────────────────────────┤
  │ context         │ nodes/context.py         │ 占位   │ 只返回 {}，V1 不查库                  │
  ├─────────────────┼──────────────────────────┼────────┼───────────────────────────────────────┤
  │ intent          │ nodes/intent.py          │ LLM    │ deepseek-flash 判断意图               │
  ├─────────────────┼──────────────────────────┼────────┼───────────────────────────────────────┤
  │ emotion         │ nodes/emotion.py         │ LLM    │ 判断情绪                              │
  ├─────────────────┼──────────────────────────┼────────┼───────────────────────────────────────┤
  │ risk_extraction │ nodes/risk_extraction.py │ LLM    │ 提取不良反应/症状/就医                │
  ├─────────────────┼──────────────────────────┼────────┼───────────────────────────────────────┤
  │ risk_engine     │ nodes/risk_engine.py     │ 纯代码 │ 规则判定 normal/medium/high           │
  ├─────────────────┼──────────────────────────┼────────┼───────────────────────────────────────┤
  │ tool_query      │ nodes/tool_query.py      │ 工具   │ 关键词命中 → 查 mock 订单 0001        │
  ├─────────────────┼──────────────────────────┼────────┼───────────────────────────────────────┤
  │ evidence        │ nodes/evidence.py        │ 纯代码 │ 把 order 压成 {source,id,content}     │
  ├─────────────────┼──────────────────────────┼────────┼───────────────────────────────────────┤
  │ adverse         │ nodes/adverse.py         │ 纯代码 │ 高风险兜底话术                        │
  ├─────────────────┼──────────────────────────┼────────┼───────────────────────────────────────┤
  │ reply           │ nodes/reply.py           │ LLM    │ 基于 intent+emotion+evidence 生成回复 │
  └─────────────────┴──────────────────────────┴────────┴───────────────────────────────────────┘

  三个 LLM 节点（intent/emotion/risk_extraction/reply）都是同一套模式：PydanticOutputParser + bind(response_format={"type":"json_object"})，因为 deepseek-flash 是思考模型，只支持 json_object、不支持 tool calling /
  json_schema（这条坑在指南里也写了）。

  二、当前存在的问题（这是真正需要你处理的）

  我本地跑了 pytest（1 passed）、mypy（no issues）、ruff（全过），CI 是绿的。但有几个「绿不代表没问题」的点：

  🔴 问题 1（最严重）：state.py 前向引用，只在 3.14 能跑，3.12 会崩

  app/agent/state.py:16 和 :23 用了 RiskInfo / EvidenceItem，但这两个类定义在 :29 / :37，在 CustomerState 后面。

  - 你本地 .venv 是 Python 3.14.6（PEP 649 延迟求值注解），所以能跑通（我实测 import app.agent.state OK）。
  - 但 CI 和 pyproject.toml 的 requires-python = ">=3.12" 是 3.12，3.12 注解是立即求值的，class CustomerState(TypedDict): risk: RiskInfo 会直接 NameError: name 'RiskInfo' is not defined。
  - 之所以 CI 还是绿的，是因为 CI 的 pytest 只收集到了 tests/test_health.py（只 import app.main，不碰 agent），从来没 import 过 state.py。

  修复：把 RiskInfo 和 EvidenceItem 挪到 CustomerState 前面（最稳妥，不依赖任何版本），并删掉那两处 # noqa: F821。

  🟠 问题 2：nodes/risk.py 是死代码，但还被 tests/test.py 引用

  - app/agent/nodes/risk.py 是旧版硬编码节点，graph 里已经不用它了（指南阶段 1 就要求删掉）。
  - tests/test.py 还在 from app.agent.nodes.risk import risk_node，而且它拼的 state 缺了 emotion 和 risk 两个 key，走到 reply_node 时会 KeyError。
  - 这个文件叫 test.py（不是 test_*.py），pytest 默认不收集，所以 CI 发现不了。

  修复：删掉 nodes/risk.py 和 tests/test.py（tests/test2.py 是阶段 1 的手动脚本，也可删），验收统一走 run.py。

  🟡 问题 3：节点返回风格不统一

  指南反复强调「只返回改动字段，不要原地修改 / 返回整个 state」，但现在：

  - ✅  risk_extraction / risk_engine / tool_query / evidence / reply → 返回 dict（正确）
  - ❌  intent.py:24 / emotion.py:24 / adverse.py:5 → 原地改 state["xxx"]=... 然后 return state（反模式）

  功能上没坏（LangGraph 会合并），但和约定不一致，建议统一成返回 {"intent": result.intent} 这种。

  🟡 问题 4：adverse 的话术会被 reply 覆盖掉

  adverse 节点写死 state["reply_draft"] = "检测到较高风险…"，但 graph 里 adverse → reply，紧接着 reply 节点又用 LLM 重新生成 reply_draft，把 adverse 写的内容覆盖了。而且 high 分支没走 evidence，reply 拿到的 evidence 是空的。

  也就是说，指南验收表里「不良反应 → 高风险处置话术」这一条，实际效果不成立。需要你定一下策略，三选一：

  1. high 分支 adverse → END（不走 reply，话术直接定稿）；
  2. 给 state 加个 risk_level 判断，reply 在 high 时走「处置话术」专用 prompt；
  3. adverse 不写话术，改成往 evidence 里塞一条「高风险，需人工处置」，让 reply 统一读证据。
